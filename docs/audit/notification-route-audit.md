# Notification route audit: current routes and source parity gaps

**Audit date:** 9 October 2026
**Purpose:** map Cosmic Forge notification categories to the remake's typed events, current notification routes, localization, and focused acceptance coverage. Implemented routes and proposed contracts are identified separately.

## Implementation follow-up

The event routes described below have now been implemented in `src/app/spaceEventNotifications.ts` and `src/i18n/spaceNotificationMessages.ts`. `withGameAudio` forwards accepted dispatch events once, including timer-generated events from `clock.advance` and accepted batch results; `App.tsx` connects those events to the existing notification stack. Starship travel uses `starShip`, rocket launch/fuel/travel uses `rocket`, hazardous weather uses `weather`, and battle completion uses `battle`. A rocket fuel-ready notice is emitted only on the first transition to full fuel. Weather notifications fire when conditions enter rain, heavy rain, or volcanic hazard; repeated conditions and clear/cloudy cycles stay silent. Battle rounds and shortened starship travel stay silent. Telescope/Launch Pad construction, system scans, star studies, missed scans, and asteroid discoveries also have typed milestone routes. Space notification copy has entries for all six supported locales. The existing focused route suite passed 6/6; the earlier clean installed-Chrome milestone, Space Mining, and Starship run passed 8/8, including rendered Telescope, Launch Pad, and system-scan notices. The focused space-event notification unit suite passed 25/25, including fuel-ready transition and six-locale copy coverage. The clean focused Chrome fuel-ready UI journey passed 1/1; the Rocket desktop and mobile screenshots were refreshed and visually reviewed, and `npm.cmd run typecheck` passed. P-08 remains open for other source notification families and the remaining Casino parity gaps. Local save feedback remains at the UI boundary, with no cloud-save claims.

## Implementation contract

1. Add one typed notification adapter for `EngineResult.events`; handle space events alongside existing routes without inferring events from UI state. Ensure the dispatch/tick boundary exposes timer-completion results and that each event is consumed once.
2. Map only player-visible milestones: starship/rocket launch and arrival, the first `space.rocket.fuel-ready` transition, a newly hazardous weather condition (plus an explicit relief policy), and battle completion. Ignore progress ticks and routine clear/cloudy changes.
3. Keep repository outcomes in the persistence/UI layer. Use local-save language and current save error codes. Source cloud notifications are not parity requirements for local storage.
4. Add or reuse message keys in each supported locale (`en`, `es`, `pt`, `de`, `it`, `fr`). Keep placeholders named and stable (`{system}`, `{rocket}`, `{asteroid}`, where used); unit tests should check all six catalogues have matching keys and interpolation.
5. Preserve the notification setting and scheduler semantics. Test classification, type, localized copy, exactly-once delivery, and no notice for events deliberately excluded above.
