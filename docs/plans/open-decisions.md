# Product decisions for MIAPLACIDUS

These decisions were supplied by the project owner on 2 October 2026 and govern the [master checklist](master-checklist.md). The filename is retained so existing links and work notes continue to resolve. No owner decision remains pending; later clarifications are recorded below.

| Topic | Decision | Consequence for the rebuild |
|---|---|---|
| Identity and scope | **MIAPLACIDUS** is a from-scratch remake of the shipped Cosmic Forge game. Preserve its player-facing mechanics and breadth across the nine source tabs, themes, story/endgame and six languages; the new Miaplaedia reference tab is a presentation addition. | Treat Cosmic Forge code and tests as read-only behavioral evidence. Extract rules and data; write a new application. Record any deliberate rule change. |
| Presentation and navigation | **Owner decision (2026-10-04; updated 2026-10-06):** keep the nine Cosmic Forge source tabs in a stable order and append a new top-level **Miaplaedia** after Settings. **Compounds follows Resources as the second visible tab whenever it is unlocked.** Omit locked main gameplay tabs entirely; the other visible tabs retain their declaration order and are not renumbered internally. Tab labels show names only, with no displayed source numbers or numeric prefixes. Settings remains the final original source tab and contains six actual settings/save/statistics/achievements/events destinations. Miaplaedia contains the seven Cosmic Forge Cosmicopedia prose documents, preserving source headings and body text in the matching locale except for required identity updates: call the game **Miaplacidus**, the player **Mia'Plac**, and the guide library **Miaplaedia**; never call the player a Cosmic Forger. | Keep Settings and Miaplaedia visible at the end of the sequence; omit locked tabs without placeholders, keep Compounds second when unlocked, and preserve the declaration order of the other tabs. Move Get Started, Story, Early/Mid/Late Concepts, End Goal, Philosophies and all remaining Cosmicopedia prose documents out of Settings and into Miaplaedia. Keep the Contact external-link action excluded. |
| Opening briefing | **Owner decision (2026-10-04, reaffirmed 2026-10-05):** permanently remove the one-screen first-run Hydrogen briefing panel and its replay button. | New and resumed runs enter gameplay directly. Do not restore the panel, replay control, or per-slot completion marker. A separate optional progression tutorial now offers resumable early-game, Settings, and Miaplaedia guidance; remaining source-step coverage stays in M-06/P-36. |
| Devices and delivery | Ship a browser game that works on desktop and responsive mobile. **No Electron app or desktop installer.** | Test wide and narrow layouts and current desktop/mobile browsers. A desktop computer uses the browser release. |
| Saving | **No cloud saves, accounts or sync.** Use multiple independent `localStorage` slots and LZString text/clipboard/file export and import. | The name field prefills the last successfully started pioneer. The slot loaded when Start is clicked is the name explicitly confirmed for that start. See the [save contract](local-save-contract.md). |
| Save compatibility | **No import or compatibility with original Cosmic Forge saves.** Saves created in MIAPLACIDUS must remain usable as the game evolves. | Introduce a versioned MIAPLACIDUS schema from the first save, validate imports, and add forward migration rungs for future MIAPLACIDUS versions. Reject old Cosmic Forge codes clearly and without changing a slot. |
| Demo | A demo is desirable, **disabled by default and enabled only by an explicit build flag**. | Full game is the normal build. Preserve the old demo's intended player-facing restrictions only in a deliberately produced demo build; test flag isolation. |
| Balance | Improvements are welcome. | Establish source behavior first, then record proposed changes with examples, player impact and tests in the affected feature plan before applying them. Gameplay parity is the baseline, not a ban on improvements. |
| Visual and audio assets | **Remake all visuals; reuse the 30 source audio assets unchanged.** | On 2026-10-04 the project owner explicitly authorized copying and using all Cosmic Forge sound assets exactly as they are. The 30 MP3 files are copied into `src/assets/audio/` and individually recorded in the asset manifest and source inventory. This approval covers audio only; source images and video remain reference material and must not be copied. |
| Localization | Keep `en`, `es`, `pt`, `de`, `it`, `fr`. The project owner gives a **quick OK** on translation quality. | Automated key/placeholder/layout checks accompany a concise review sample and final owner signoff. |
| Analytics | **No analytics system for now.** | Do not implement telemetry collection, consent screens, endpoints or analytics preferences. Cosmic Rip's in-game telemetry is a gameplay resource and stays. |

## P-55 Statistics semantics decisions (12 October 2026)

The owner selected **Use the documented remake behavior** for the three Statistics rows whose semantics had been pending. Keep the current MIAPLACIDUS behavior and do not change these values to mirror Cosmic Forge's source-specific scopes:

- **Time Played / Run Time:** keep active-lifetime time and simulation-run time. Existing saves do not contain a reconstructable wall-clock start anchor, so do not reinterpret or fabricate elapsed history.
- **Star Ship Distance Travelled:** keep completed-route This Run and Lifetime totals; show in-flight progress on the Starship page. Cosmic Forge's two columns instead alias current-trip progress/full distance and reset on rebirth.
- **Enemy Total Defence Overcome:** keep Not Applicable in the remake. Cosmic Forge's label refers to a single-battle start-minus-current enemy-power delta; the remake has no cumulative lifetime meaning for that row.

This resolves the owner-decision subtask under P-55, not its source-value audit. The controlled row comparisons and remaining checklist evidence stay open in the [Statistics parity plan](statistics-presentation-parity.md).

## Phase 6 owner decisions (12 October 2026)

- **P-29 battle audio fidelity (owner reaffirmed 13 October 2026):** implement Cosmic Forge's per-visible-shot and per-confirmed-death attempt timing and eligibility, including its callback/cooldown behavior. Keep combat damage and outcomes unchanged; the aggregate approximation is not the accepted endpoint. The transient unit-level presentation derives visible shot candidates and tracks source-shaped health crossings. It reconciles each `(round, side, fleet)` group independently, keeping modeled crossing times for matching groups even if another group in the round differs. Unmatched confirmed deaths still use aggregate event-receipt timestamps, which are not source-parity evidence. The engine events lack victim identities and source hit timestamps, so exact timing for every confirmed death remains open; see the [battle audio audit](../archive/audits/P29-battle-audit-2026-10-11.md).
- **Black Hole Instability expiry feedback:** add the source result modal and keep MIAPLACIDUS's existing stabilization toast. The modal remains independent of the notification preference; the toast remains preference-gated. See the [expiry dialog audit](../archive/audits/p44-random-event-expiry-dialog-audit-2026-10-12.md).
- **P-29 death-audio timing refinement (13 October 2026):** the explosion cooldown is global in Cosmic Forge. MIAPLACIDUS now sends every modeled per-unit crossing time to the audio gate when the round-wide source-crossing total equals the engine-confirmed total, even if fleet attribution differs. Per-fleet matches still govern unit-specific explosion visuals. When the round totals differ, unmatched confirmed deaths still use event-receipt time, which remains outside acceptance. Combat damage and outcomes are unchanged; P-29 stays open until every confirmed death has source timing and cadence evidence. See the [battle timing audit](../archive/audits/p29-battle-death-timing-feasibility-audit-2026-10-13.md).
- **P-29 direct callback implementation update (13 October 2026):** the battle renderer now attempts explosion audio synchronously when its source-shaped presentation simulation crosses an individual unit's health threshold; it no longer makes receipt-time or delayed batch explosion attempts. Since the independent simulation can disagree with the unchanged aggregate engine's confirmed casualty counts, this can produce an audio attempt for an unconfirmed death or omit a confirmed one. It is not source-parity evidence for every confirmed casualty; continue implementation toward that requirement without changing damage or outcomes.
- **P-29 confirmed-only timing follow-up (13 October 2026):** direct speculative audio was removed. Audio now plays only after a source-shaped `(round, side, fleet)` casualty count matches engine-confirmed deaths, passing the stored `sourceCrossingAtMs` into the cooldown to preserve ordering. This timestamp does not backdate playback: because the engine confirms deaths after aggregate 250 ms resolution, the sound still waits for confirmation; unmatched confirmed deaths are silent. This prevents unconfirmed sounds without reproducing source audible timing for every confirmed death. P-29 remains open; no combat damage or outcomes changed.
- **P-29 source-timed callback update (owner direction 13 October 2026):** the renderer now attempts explosion audio at each modeled per-unit zero-health crossing and applies the shared strict >140 ms cooldown immediately. This supersedes confirmed-only delayed cues in current code. Aggregate engine events still govern visuals and combat outcomes are unchanged. Because sidecar crossings can diverge from pooled confirmed losses, P-29 remains open for cadence and source/model parity review. See the [battle timing audit](../archive/audits/p29-battle-death-timing-feasibility-audit-2026-10-13.md).
- **Near-capacity Resource collection:** keep the remake's full-unit storage rule; a manual collection is rejected unless one full unit fits, preserving the storage invariant. See the [capacity-boundary audit](../archive/audits/p55-resource-collection-capacity-boundary-audit-2026-10-12.md).

## Working technical decisions

- TypeScript, Vite and React for the browser UI; semantic HTML and responsive CSS. The simulation remains framework-independent and deterministic.
- Vitest for pure rules and Playwright for browser functional areas, following the old project's area-based test and debug approach.
- LZString 1.5.0 for compressed local slots and portable codes. The package is already pinned in the manifest and lockfile.
- Keep future implementation choices in the feature plan that needs them. Amend this record only when the owner changes a product decision; then update the master checklist and affected contracts together.

**Energy after rebirth (owner direction 12 October, reaffirmed 13 October 2026):** the owner directed MIAPLACIDUS to follow Cosmic Forge. Dyson Sphere stage 2's 1.25x plant-rate mutation is run-scoped: source rebirth restores initial plant rates and replays Optimized Power Grids, but does not replay the Dyson mutation. A new run therefore retains permanent Dyson technology while its plant-rate boost is inactive. The remake now stores this effect as run state and clears it on rebirth. See the [Dyson rebirth audit](../archive/audits/p55-dyson-production-rebirth-audit-2026-10-12.md) and [Energy rebirth audit](../archive/audits/p55-energy-rebirth-audit-2026-10-12.md).

**Energy rebirth follow-up (12 October 2026):** the same source boundary also resets stage 1's doubled battery capacities and leaves the power grid off unless persistent Dyson stage 5 grants Infinite Power. MIAPLACIDUS now resets the run-scoped stage 1 capacity flag and only restores grid/Infinite Power for stage 5. Stage 4 is permanent technology but does not by itself reactivate Infinite Power in a new run. The v53-to-v54 migration derives the new run flag from stage 1 ownership to preserve the existing save's live behavior. See the [Energy rebirth audit](../archive/audits/p55-energy-rebirth-audit-2026-10-12.md).

**Energy legacy-save and Statistics unit follow-up (13 October 2026):** the v52→v53 migration now leaves Dyson's run-only plant-rate boost inactive for saves with a prior rebirth, while preserving permanent stage 2 ownership. Numeric Total Energy, Total Production, and Total Consumption values now use Cosmic Forge's `kJ / s` unit across all six locales; the Infinite Power Total Energy status remains `∞ DYSON ∞`. This is a static source-to-renderer correction; migration fixtures, matched values, and rendered review remain open. See the [Dyson migration audit](../archive/audits/p55-dyson-v52-migration-audit-2026-10-13.md) and [Energy rate-unit audit](../archive/audits/p55-energy-statistics-rate-unit-audit-2026-10-13.md).
