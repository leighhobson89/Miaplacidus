### AP Anticipated source comparison (10 October 2026)

Cosmic Forge's Statistics getter map registers `getStatApAnticipated` (`constantsAndGlobalVars.js:977`); the getter returns the run-local `apAnticipatedThisRun` accumulator (`:5018-5019`), and its setter adds each supplied value (`:5684-5685`). A confirmed starship launch adds the destination's base `ascendencyPoints` unconditionally (`ui.js:6593-6606`). A later destination scan calls `generateDestinationStarData` (`drawTab5Content.js:974-977`); that generator obtains the civilization through `generateCivilizationLevel` (`game.js:14218-14235`), which adds the base AP again only for Industrial or Spacefaring civilizations and only when a numeric profile value is present (`:14326-14344`). Thus, a launched but unscanned destination contributes once in the source; an eligible scanned destination contributes at launch and scan; an ineligible or missing-value scan contributes no scan increment. The source adds through accepted actions rather than maintaining a distinct-scanned-system set.

The source counter is saved and restored (`constantsAndGlobalVars.js:1829`, `:2196`) and reset by `resetAllVariablesOnRebirth` (`:1384`, `:1555-1561`). Before the implementation update below, the remake computed the row with `selectRunApAnticipated` (`src/engine/selectors.ts:111-133`): distinct encountered IDs whose civilization is Industrial or Spacefaring contribute their profile base AP once, while ineligible encounters and missing profiles contribute zero. That former implementation did not add AP on launch or a second amount on an eligible scan. Rebirth creates a fresh run without encounters in `metaProgression.ts:121-160`, so the derived remake value returns to zero, matching the source counter's run boundary.

Pre-correction coverage proved the former selector interpretation; its assertions were superseded by the launch/scan accumulator implementation below and have not yet been run. The former navigation contract and selector comment incorrectly described scanned-system counting as source parity. No controlled source-save value comparison has been made, so P-55 remains open for the broader source-row audit.
