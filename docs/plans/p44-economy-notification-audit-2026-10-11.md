# P-44 Resource, Compound, and Research notification crosswalk

Audit date: 11 October 2026. Scope is player-visible action completion and ordinary unavailable/invalid outcomes for Resources, Compounds, and Research. This is a copy and routing review; no behavior or catalog changes were needed.

## Crosswalk

| Action/outcome | Cosmic Forge behavior | MIAPLACIDUS mapping | Result |
| --- | --- | --- | --- |
| Sell a Resource or Compound | `game.js` uses `notificationSoldMaterialSymbolBefore` or `notificationSoldMaterialSymbolAfter` in `sellResource()` / `sellCompound()` (around lines 5229–5391), selecting currency placement for the active currency. | `src/app/economySaleNotifications.ts` routes only an accepted `resource.sold` event to `economyMessages.ts:saleNotification`; `formatCurrency()` supplies locale-appropriate currency placement. The same route covers Resources and Compounds. | Correct semantic result in all six locales; failed/empty sales do not show a success notice. |
| Create a Compound | `game.js:createCompound()` uses `notificationCompoundCreated` or `notificationCompoundCreatedWithWaste` (around lines 5315–5359), reporting the created amount and recipe inputs, and warning when storage discards output. | `src/app/compoundCreatedNotifications.ts` routes only the accepted manual `compound.created` event to `economyMessages.ts:compoundCreatedNotice`, listing recipe inputs with localized names. Automatic production does not generate a manual-action toast. | Success copy and route are appropriate across all six locales. The source's waste branch has no direct counterpart in this typed manual-create route; capacity and command-state behavior needs a separate mechanics review before adding waste copy. |
| Fuse Resources | `game.js:fuseResource()` uses `notificationFusionDiscovered`, `notificationFusionEnergyLoss`, or `notificationFusionStorageLimited` (around lines 5137–5203). | `src/app/EconomyPanes.tsx:ResourceFusionDetails` routes accepted `economy.fusion.completed` events to `fusionDiscoveredNotice`, `fusionEfficiencyNotice`, or `fusionStorageNotice` in `economyMessages.ts`. The selection includes first discovery, efficiency loss, and storage loss. | Success and loss outcomes are represented in all six locales. |
| Invalid Fusion preview / insufficient input | Cosmic Forge's `notificationFusionInvalidPreview` is raised only when parsing its displayed preview fails. | The remake computes a typed preview and does not parse rendered text. Whole-number and insufficient-source cases use the localized inline reasons `fusionWholeAmount` and `fusionSourceShort`; invalid inputs cannot reach the completion route. | No toast port is needed for this source-internal preview failure; ordinary user-facing constraints remain explained inline. |
| Storage reaches capacity | Cosmic Forge `maybeNotifyStorageFull()` uses `notificationStorageFull` and provides an Increase Storage action (`game.js` around lines 859–890). | `src/app/economyActionNotifications.ts:createStorageFullNoticeHandler()` uses `storageFullNotice`, offers the matching purchase action, and warns with `purchaseUnavailable` if that action cannot be accepted. | Correct mapped outcome and failure feedback across all six locales. |
| Buy storage / autobuyers | Cosmic Forge exposes these purchases but does not emit a corresponding single-purchase or autobuyer-purchase success toast. | `dispatchEconomyStoragePurchase()` routes only accepted `storage.increased` events; `dispatchEconomyAutobuyerPurchase()` routes only accepted `purchase.completed` events to `storageIncreasedNotice` and `autobuyerPurchaseNotice`. | These are remake additions. Autobuyer copy is count-neutral for single and bulk purchases (P-45); rejected autobuyer purchases retain their inline affordability reason. |
| Research technology | Cosmic Forge calls the `techNotify*` descriptions on completion (catalogue in `descriptions.js:542–599`; localized strings in `localization.json`). | `src/app/App.tsx` watches for newly researched technology IDs and routes through `technologyNotificationText()` in `src/i18n/technologyNotificationMessages.ts`. The existing source crosswalk records 57 technologies × six locales mapped. | Completion route and locale coverage are accounted for. Standard unaffordable or prerequisite-blocked research has no source toast; the remake exposes the RP shortfall/prerequisite status inline in the Tech Tree. |

## Locale and validation status

The relevant typed message families are present for `en`, `es`, `pt`, `de`, `it`, and `fr`: `saleNotification`, `compoundCreatedNotice`, the four fusion notices, `storageIncreasedNotice`, `storageFullNotice`, `autobuyerPurchaseNotice`, and `purchaseUnavailable`. Research completion uses the six-locale technology catalogue. This audit was a static source/copy review; no tests, build, typecheck, browser review, or other checks were run. Runtime wording/layout and the Compound storage-waste mechanics remain for the broader P-44 validation pass.
