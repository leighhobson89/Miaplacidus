The six non-telemetry rows' current value, scope, and action boundaries match the source behavior or the already documented target representation. Cosmic Rip progress is permanent in the target state and preserved through rebirth; telemetry earned and GP spent are in `statistics`, serialized with the rest of the state. Saves before schema v38 initialize these two historical counters to zero because that history was not tracked ([migration](../../../src/engine/state.ts#L3645-L3688)). The v52→v53 migration converts the previously under-rate telemetry counter to source-equivalent units while retaining finite fractional precision; current saves use schema v54 ([migration](../../../src/engine/state.ts#L4108-L4200)).

## Corrected precision mismatch

Cosmic Forge adds each finite positive telemetry delta directly to its all-time accumulator without a safe-integer cap ([source accumulator](../../../../cosmicForge/cosmicForge/constantsAndGlobalVars.js#L5941-L5949)). MIAPLACIDUS previously capped live accumulation at `Number.MAX_SAFE_INTEGER` in [`advanceCosmicRip`](../../../src/engine/cosmicRip.ts#L337-L360) and capped the schema-v53 converted history at the same value ([migration](../../../src/engine/state.ts#L4155-L4188)). This made a valid finite saved counter above that threshold fall to the cap on its next production tick, and clipped finite v52 history during unit conversion.

Both paths now preserve the source-equivalent finite `number` value and saturate only if addition/conversion exceeds JavaScript's finite range. This keeps the validator's finite-value invariant and avoids discarding the accepted larger telemetry history. Values below the representable precision of a large IEEE-754 number naturally behave as in the source runtime.
