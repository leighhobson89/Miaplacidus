# P-44 Resources, Compounds, and Energy notice-copy follow-up

Audit date: 12 October 2026. This static follow-up compares Cosmic Forge's live economy notice callsites and six-locale source values with MIAPLACIDUS's current notification routes. It does not modify the estimate document.

## Source-to-remake routes

| Action or outcome | Cosmic Forge source UI and message | MIAPLACIDUS route | Finding |
| --- | --- | --- | --- |
| Sell one Resource or Compound | `game.js:sellResource()` / `sellCompound()` call `notificationSoldMaterialSymbolBefore` or `notificationSoldMaterialSymbolAfter` (`game.js:5229-5235,5385-5391`), selected by the currency symbol. The six locale blocks use the same sale wording and `{amount}`, `{material}`, `{cash}`, and `{currency}` values. | `EconomyPanes.tsx` sends the selected good sale to `economySaleNotifications.ts:15-45`, which formats localized cash and renders `saleNotification` from `economyMessages.ts`. | Wording maps in all six locales. `formatCurrency()` supplies locale-aware currency placement and precision in place of the source's separate before/after templates. |
| Sell all Resources or Compounds | `sellAllUnlockedResources()` and `sellAllUnlockedCompounds()` show `notificationSoldAllResourcesSymbolBefore/After` or `notificationSoldAllCompoundsSymbolBefore/After` (`game.js:5251-5292,5399-5440`). | The remake exposes per-good sale controls and does not have an aggregate sell-all action or notification route. | No aggregate target notice is routed because the corresponding action is absent. |
| Create a Compound | `createCompound()` uses `notificationCompoundCreated` or `notificationCompoundCreatedWithWaste` (`game.js:5302-5359`). The success template is localized in en/es/pt/de/it/fr and joins the displayed recipe parts with `notificationParts.join(', ')`. | The manual Create button in `EconomyPanes.tsx` routes an accepted `compound.created` event through `compoundCreatedNotifications.ts` to `compoundCreatedNotice`. | The six `compoundCreatedNotice` templates match the source success templates. The target previously inserted a locale conjunction with `Intl.ListFormat`; it now joins recipe parts with `", "`, matching the source callsite. Source over-capacity crafting emits a waste warning; the remake disables a create that would exceed storage and reports the inline failure instead, so there is no accepted waste-result event to notify. |
| Fuse a Resource | `fuseResource()` selects `notificationFusionDiscovered`, `notificationFusionEnergyLoss`, or `notificationFusionStorageLimited` (`game.js:5137-5203`). | `ResourceFusionDetails` in `EconomyPanes.tsx:879-911` routes accepted fusion events to the three `fusion*Notice` catalog entries. | Target messages preserve and expose generated/stored amounts and separate efficiency loss from storage loss, which the target event records independently. They are localized outcome paraphrases rather than verbatim copies of the source templates. Keep this copy adaptation visible for the wider P-44 review. |
| Storage full or storage purchase | Source `maybeNotifyStorageFull()` uses `notificationStorageFull` and an Increase Storage action (`game.js:819-890`); the bulk storage command uses `notificationIncreasedAllStorage` (`game.js:750-795`). | `createStorageFullNoticeHandler()` maps the full state and action in `economyActionNotifications.ts`; accepted individual purchases use `storageIncreasedNotice`. | The full-storage message and action map to the source in all six locales. A single-good purchase success notice is an owner-requested remake addition; the source notice is for a bulk increase. |
| Autobuyer purchase | No autobuyer purchase-success toast was found in the source Resource or Compound UI. | `dispatchEconomyAutobuyerPurchase()` routes accepted purchases to `autobuyerPurchaseNotice`. | Owner-requested remake addition; no source success string is missing from the translation map. |
| Energy purchase and power-plant sale | `drawTab2Content.js` purchases Energy buildings without a success toast. `drawTab2Content.js:170,260,350` also exposes source power-plant sale actions; `game.js:sellBuilding()` refunds 40% and emits `notificationSoldPowerPlant` (`game.js:10096-10167`). | Energy purchases in `EconomyPanes.tsx` update the owned/value state inline and have no separate success notice. No building-sale command or Energy power-plant sale control exists in the target source tree. | Purchase presentation has no source success toast to reproduce. The source plant-sale action and notice have no target route; this is a feature-coverage gap, not a string that can be corrected in isolation. |

## Checks and remaining scope

The only code change in this follow-up is the source-matching comma separator in `compoundCreatedNotifications.ts`. No estimate or percentage changed, no Phase 6 ticket was closed, and no test, build, typecheck, browser check, or save interaction was performed. Cosmic Forge files were read only. P-44 remains open for the larger source-to-renderer review, including the documented Compound storage-waste difference and Energy plant-sale route.
