# P-29 source-timed battle death callback feasibility audit

**Date:** 13 October 2026

The owner reaffirmed that battle death audio should follow Cosmic Forge's source timing and eligibility while leaving MIAPLACIDUS combat damage and outcomes unchanged.

## Source behavior

Cosmic Forge runs its battle movement and goal assignment from the animation-frame game loop (`game.js:9563-9720`). It iterates individual player and enemy units; a successful attack applies damage to the attacker's current visible target, immediately handles Power Siphon healing, and triggers that unit's death animation/audio path at its own health crossing (`game.js:14991-15052`). The explosion sound is chosen at the callback and attempts inside the strict 140 ms cooldown are suppressed (`ui.js:13440-13518`). The crossing order and sound eligibility therefore depend on per-unit health, positions, visibility, target goals, and RAF cadence.

## Current remake boundary

MIAPLACIDUS resolves battle state in [`spaceMechanics.ts`](../../../src/engine/spaceMechanics.ts#L1090). It computes one count-scaled damage value for each attacking fleet, including a `×60` multiplier, subtracts that amount once from an aggregate fleet-class health pool, and then derives confirmed class losses. The opposing side uses the same aggregate-pool approach. Death events preserve round, side, class, attack order, and confirmed loss count, but do not contain per-unit health or target-crossing time. The battle presentation can replay those confirmed counts only at the event receipt boundary.

Algebraically splitting the `×60` damage multiplier would produce a substep ordinal, but neither the resolver nor its 250 ms timer defines those substeps as source simulation frames. Assigning timestamps inside the round would invent a clock and still would not reconstruct Cosmic Forge's per-ship visibility, target selection, or immediate retargeting. Playing a cue from speculative renderer damage could also report an unconfirmed casualty.

An exact source-like death stream would require a per-ship health, target identity, and deterministic tick model. Replacing aggregate resolution with that model puts fleet losses, battle duration, Power Siphon healing, and target order at risk, so it cannot currently satisfy the owner's no-outcome-change constraint. No safe source-timed implementation was identified in this feasibility review. P-29 remains open; count-based or event-receipt-time callbacks are not acceptance evidence. No code, tests, builds, or browser checks were run for this feasibility review.

**Owner follow-up (13 October 2026):** after this feasibility note, the owner reaffirmed that implementation should match Cosmic Forge's death callback timing and eligibility while preserving combat outcomes. The renderer now captures one callback timestamp per confirmed visible casualty and shares it between the explosion animation and sound cooldown; that timestamp still reflects when the remake receives the aggregate death record, not the source per-unit health crossing. The feasibility finding is not an accepted endpoint. Continue P-29 implementation until source timing is reproduced or the owner changes direction.

**Conditional source-time implementation update (13 October 2026):** `SpaceBattlePresentation.tsx` now tracks a transient source-shaped per-unit health timeline. Its crossing times are used only when the sidecar's per-round, per-fleet counts reconcile with every engine-confirmed loss in that round. These modeled-source callbacks retain individual timestamps and crossing order; unmatched confirmed deaths use an explicitly typed aggregate-event-receipt timing origin, shared across losses from that event. That fallback remains outside the owner's acceptance requirement. This advances the implementation beyond the feasibility note's prior receipt-time-only state, while exact source timing for every confirmed death remains open. No tests or browser checks were run.

**Independent casualty-group reconciliation refinement (13 October 2026):** the presentation now reconciles each `(round, side, fleet)` group independently. A matching group keeps its individual modeled crossing timestamps even if a different group in the same round has a count mismatch. Only unmatched confirmed losses use aggregate event-receipt timing. This improves the mapped cases without changing combat damage or outcomes; it does not satisfy the source-timing requirement for mismatched groups. No tests or browser checks were run.

**Round-wide explosion-audio mapping refinement (13 October 2026):** Cosmic Forge's explosion cooldown is global, so audio does not require the source sidecar to agree with the engine on fleet attribution. When total sidecar crossings equal total engine-confirmed deaths for a round, MIAPLACIDUS now feeds every individual crossing timestamp to the audio cooldown in global time order. Per-fleet matches still govern which unit receives each explosion visual; remaining confirmed visuals use the remaining modeled crossing times when the round total matches. If round totals differ, unmatched confirmed losses retain event-receipt timing. That mismatch fallback is still not source parity. Combat damage and outcomes are unchanged; no tests or browser checks were run.

**Direct source-model callback implementation update (13 October 2026):** audio is now attempted synchronously inside the visible presentation simulation when an individual modeled unit crosses zero health; receipt-time fallback and delayed batch audio attempts were removed. This follows the source's callback shape more closely, but the presentation simulation remains independent and stochastic while the engine emits only aggregate casualties every 250 ms. A model death can therefore sound without a matching confirmed engine casualty, and a confirmed casualty can lack a modeled crossing. This mismatch does not satisfy the owner's requirement that every confirmed death have source timing and eligibility. Combat damage and outcomes are unchanged. No tests or browser checks were run.

**Confirmed-only correction (13 October 2026):** direct speculative crossing audio was removed. The renderer now attempts an explosion only after a modeled casualty group matches the engine-confirmed `(round, side, fleet)` count; it passes each stored crossing timestamp to the audio cooldown. Since the engine publishes casualties after aggregate 250 ms resolution, the sound is played at confirmation time rather than the original source crossing time. A mismatched confirmed group gets no fallback sound. This avoids unconfirmed audio while leaving source-timed audible callbacks for every confirmed death unresolved. Combat damage and outcomes remain unchanged. No tests or browser checks were run.

**Owner-directed source-timed callback reimplementation (13 October 2026):** after the owner selected Cosmic Forge behavior, the battle presentation now attempts explosion audio synchronously when the transient per-unit model crosses zero health. The callback uses the existing shared strict >140 ms global cooldown and runs in crossing order; aggregate reconciliation no longer gates audio. Aggregate engine events still determine confirmed death visuals, and the combat resolver, damage, and outcomes remain unchanged. A sidecar crossing may not correspond to a pooled confirmed loss, and some confirmed losses may have no modeled crossing, so this presentation-only implementation does not close P-29. Source/model parity and cadence evidence remain required. No tests or browser checks were run.
