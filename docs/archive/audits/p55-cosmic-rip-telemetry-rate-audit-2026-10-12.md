# P-55 Cosmic Rip telemetry rate audit (12 October 2026)

Cosmic Forge stores the Sensor Buoy and Rip Research Orbiter rates as `0.04` and `0.07` per update tick in [`resourceDataObject.js`](../../../../cosmicForge/cosmicForge/resourceDataObject.js#L991-L1009). Its update interval is 10 ms ([`constantsAndGlobalVars.js`](../../../../cosmicForge/cosmicForge/constantsAndGlobalVars.js#L51-L52)); [`updateRipTelemetryDelta`](../../../../cosmicForge/cosmicForge/game.js#L2781-L2801) divides the per-tick rate by 10 and multiplies by elapsed milliseconds. Thus the source-equivalent per-second rates are 4 telemetry/s per buoy and 7 telemetry/s per orbiter. The offline path multiplies the stored rates by `TIMER_RATE_RATIO` 100 and elapsed seconds (`game.js:12670-12673,12718,12760-12762`), giving the same rates. Source sums quantity times per-tick rate in [`calculateRipTelemetryRatePerTick`](../../../../cosmicForge/cosmicForge/game.js#L2835-L2841).

MIAPLACIDUS uses per-second values in [`COSMIC_RIP_UPGRADES`](../../../src/content/cosmicRip.ts#L20-L30), and [`cosmicRipTelemetryRate`](../../../src/engine/cosmicRip.ts#L142-L147) multiplies each value by its owned quantity. [`advanceCosmicRip`](../../../src/engine/cosmicRip.ts#L337-L355) accrues that rate over elapsed seconds into both `permanent.cosmicRip.telemetryData` and `statistics.lifetimeCosmicRipTelemetryDataEarned`. The two constants now use 4 and 7, so one of each generates 11 telemetry/s, matching the source's 0.11 per 10 ms tick. Source adds each positive gain to the balance and `allTimeRipTelemetryDataEarned` independently of research spending (`game.js:2799-2801`); the getter reads that saved all-time field ([`constantsAndGlobalVars.js`](../../../../cosmicForge/cosmicForge/constantsAndGlobalVars.js#L5484-L5485)), which is captured/restored on save (`:1821,2188`). Source's run counter resets on rebirth (`:1460`), while the Statistics Run cell is Not Applicable.

**Save-history boundary:** prior MIAPLACIDUS saves accrued both the telemetry balance and earned-history counter at one hundredth of the corrected rate. The v52→v53 migration scales saved lifetime-earned history by 100 and reconstructs current balance as `100 * old balance + 99 * C`, where `C` is telemetry research cost already paid for completed technologies plus active research. This avoids scaling amounts already spent. Older saves reach this rung through the migration chain to current save schema v54. Saves predating the lifetime-earned counter retain zero for that unrecoverable history; their balance still uses known paid research costs. Eight-decimal target accrual rounding limits balance reconstruction precision. Valid finite balances above `Number.MAX_SAFE_INTEGER` are preserved; only a converted value beyond JavaScript's finite number range saturates to `Number.MAX_VALUE`.

The later P-55 row-value review found the lifetime-earned statistic also needs source-like uncapped finite accumulation. Its live accumulator and the v52→v53 history conversion now retain finite values above `Number.MAX_SAFE_INTEGER`, saturating only on overflow. Current saves use schema v54. This correction is recorded with the seven-row source comparison in the [Cosmic Rip Statistics value audit](p55-cosmic-rip-statistics-value-audit-2026-10-12.md).

No tests or checks were run. The focused source/renderer review establishes the rate conversion; controlled nonzero source-save comparison and rendered review remain open under P-55.
